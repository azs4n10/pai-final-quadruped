ことばで動く四足配送ロボット

ローカルLLM × 強化学習（PPO）による、日本語指示での目標到達歩行 ― Physical AI 応用1 最終課題

1. 概要

日本語で「赤い柱に寄ってから青い柱へ行き、最後はホームに戻って」と指示すると、犬型の4脚ロボットが指示どおりの順に各地点を歩いて回るシステムを、物理シミュレータ MuJoCo 上に実装した。指示の解釈はローカルで動く LLM（gemma4 / Ollama）が担当し、歩行そのものは強化学習（PPO）で獲得した「指定したゴールまで歩く」方策が担当する。ロボットは MuJoCo のモデル記述（MJCF）で自作し、初版で使った標準モデル Ant（クモ型）から作り直した。

2. 目的

  • 脚ロボットは段差や不整地に強く、倉庫・施設内の巡回や配送への応用が期待される。現場の人が専門知識なしに「どこへ行ってほしいか」を言葉で伝えられれば使い勝手が大きく上がる。
  • そこで「言葉の理解（LLM）」と「身体の制御（強化学習）」を役割分担させ、それぞれ得意な部分だけを任せる構成で、言葉から歩行までを一貫して動かすことを目標とした。
  • 機密性の高い現場でも使えるよう、LLM は外部 API を使わずローカルで動かす。

3. 手法

(1) 犬型ロボット（自作）　実在の四足ロボットに近い構成にした。左が初版の Ant、右が今回作った犬型である。

体胴体（箱形、6 kg）と頭、脚 4 本。各脚は外転・股・膝の 3 関節で計 12 関節、全体で 12.1 kg、立った高さ約 0.31 m
制御関節は位置制御（PD、比例ゲイン 60、最大トルク 30 N·m）。方策の出力は「立ち姿勢からの関節角のずれ」（±0.4 rad）で、50 Hz で更新
観測（51次元）胴体の高さ・重力の向き・速度・角速度（胴体座標系）、12 関節の角度と速度、直前の行動、ゴールの方向（胴体座標系 2 / 世界座標系 2）と距離（5 m で頭打ち）
報酬ゴールに近づいた速さ ＋ ゴールの方を向いていること ＋ 着地時の足の滞空時間 ＋ 到着ボーナス 10（半径 0.6 m 以内）− 胴体の傾き − 腹ばい（胴体が低いこと）− 行動の急な変化 − トルクの大きさ。胴体が 0.2 m より下がるか大きく傾いたら転倒として終了
ゴールの出し方現在地から 1.5〜5 m・ランダムな方向に置き、到着するたびに次のゴールを出し直す（1 エピソード 30 秒の中で何度も到達を練習）。出発時の向きもランダム
学習PPO（Stable-Baselines3）、16 並列環境、方策・価値とも 256×256 の MLP、観測・報酬の正規化あり、CPU のみ

(2) LLM プランナー　地点名と座標の一覧をシステムプロンプトで与え、指示を {"route": [...], "reply": "..."} の JSON に変換させる。Ollama の構造化出力（JSON Schema）で route の要素を地点名の列挙型に制限し、存在しない地点を出力できないようにした。LLM が使えない場合は、文中の色名を拾う簡易的な変換に切り替わる。

(3) 実行　経由地を 1 つずつゴールとして方策に渡し、到着したら次の経由地へ切り替える。

4. 開発の経緯

  • 初版（Ant）：まず Gymnasium 標準の Ant を同じゴール到達課題に作り替えて学習させ、日本語指示での経由地巡回まで動かした（700 万ステップで到達率 99%）。ただ、胴体から脚が放射状に伸びたクモのような形で、配送ロボットとしては見た目の印象がよくなかった。
  • 犬型に作り直す：胴体の下に脚が伸びる犬型を MJCF で一から作った。脚が胴体の真下にあるぶん倒れやすいので、関節をトルク直接指定ではなく位置制御にし、方策には「立ち姿勢からのずれ」だけを出させた。こうすると学習の初めから立った状態を保てる。
  • 腹ばい歩きの修正：最初の報酬（近づく速さ・向き・傾き・なめらかさ）では、100 万ステップの時点で胴体を低く下げ、脚をたたんだまま這うように進む動きになった。ゴールには着くが、犬の歩き方ではない。そこで「胴体が 0.28 m より低いと減点」「転倒判定の高さを 0.17 → 0.2 m に上げる」「足が着地した瞬間に、それまで浮いていた時間に応じて加点（0.2 秒より長く上げていれば得）」の 3 つを加えて学習し直したところ、胴体を起こして脚を交互に踏み出す歩き方になった。
  • 学習の打ち切り：学習は 2,500 万ステップの予定だったが、同じ PC で動いていた別の処理と合わせてメモリが不足し、約 200 万ステップ（約 22 分）の時点で止まった。その時点で到達率 98%（100 回）に達しており、初版より速く確実だったため、このチェックポイントを採用した。

6. 工夫した点

  • 言葉と身体の役割分担：LLM には経由地の列を出させるだけにして、関節の動かし方には関わらせない。歩行方策は「ゴールまで歩く」ことだけを学ぶので、新しい指示や地点の組み合わせにも学習し直さずに対応できる。
  • ロボットの自作と位置制御：実在の四足ロボットに近い犬型を作り、位置制御と「立ち姿勢からのずれ」を出力とする設計で、200 万ステップ（CPU で約 22 分）という短い学習で実用的な歩行を得た。
  • 歩き方を報酬で整える：腹ばいで進む抜け道を、胴体の高さの減点と足の滞空時間の加点で塞ぎ、犬らしく脚を上げる歩き方に変えた。
  • ゴールを胴体から見た向きで与える：ゴール方向を胴体座標系に変換して観測に加え、「ゴールの方を向いている」ことにも小さく報酬を与えた。これで頭を進行方向に向けて歩くようになった。
  • 到着したらゴールを出し直す：1 エピソードに何度もゴールを出すため、「止まる・曲がる・また歩く」を集中的に経験できる。学習中は 5 m 以内のゴールしか出さなかったが、10 m を超える区間でも到達できた。
  • LLM 出力の型を制限：JSON Schema の列挙型で、存在しない地点や不正な形式が実行系に渡らないようにした。
  • 評価に基づく判断：ロボットの形の変更やモデルの採用は、100 回の到達試験と経路ごとの 20 回試験の数字で比べて決めた。

7. 課題と考察

  • 失敗の内訳：到達試験 100 回の失敗は 2 回で、1 回は出発 2.4 秒後の転倒、1 回はゴールまで 3.2 m の地点でしゃがんだ姿勢（胴体の高さ 0.22 m）のまま止まり、時間切れになった。経路試験 60 回の失敗は 1 回で、青い柱に着いた 1.5 秒後、ホームへ向きを変える途中の転倒だった。止まる失敗には、一定時間近づけなければ立ち姿勢に戻してから歩き直す回復動作、転倒には起き上がり動作の学習が有効と考えられる。
  • 学習量：メモリ不足で学習が 200 万ステップで止まったため、より長く学習した場合の歩き方の洗練や安定性の向上は確かめられていない。
  • LLM の応答時間：4 GB の GPU で 4B 級のモデルを動かすため、1 回の変換に数十秒〜1 分半かかった。実用には小型モデルへの特化（ファインチューニング）や、よく使う指示のキャッシュが必要。
  • 今後：障害物のある環境での経路計画、カメラ画像からの地点認識（VLM）、地形やモデル誤差をランダム化した学習による実機の四足ロボットへの sim-to-real。

8. 実行方法

コード一式は GitHub リポジトリ https://github.com/azs4n10/pai-final-quadruped に置いた（README 参照）。主なファイル：goal_dog.py（犬型ロボットと環境）、goal_ant.py（初版の環境）、train_goal.py（学習）、planner.py（LLM）、demo.py（指示の実行と録画）、evaluate.py（評価）、make_video.py（動画の作成）。
例：python demo.py --robot dog --text "黄色い柱に荷物を届けたら帰ってきて"

使用ツール：MuJoCo 3.12 / Gymnasium 1.3 / Stable-Baselines3 2.9（PPO）/ Ollama（gemma4:e4b）/ Python 3.12。動画は等速（倍速なし）。
