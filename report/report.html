ことばで動く四足配送ロボット

ローカルLLM × 強化学習（PPO）による、日本語指示での目標到達歩行 ― Physical AI 応用1 最終課題

1. 概要

日本語で「赤い柱に寄ってから青い柱へ行き、最後はホームに戻って」と指示すると、犬型の4脚ロボットが指示どおりの順に各地点を歩いて回るシステムを、物理シミュレータ MuJoCo 上に実装した。指示の解釈はローカルで動く LLM（gemma4 / Ollama）が担当し、歩行そのものは強化学習（PPO）で獲得した「指定したゴールまで歩く」方策が担当する。ロボットは MuJoCo のモデル記述（MJCF）で自作した。初版で使った標準モデル Ant（クモ型）から犬型に作り直し、さらに歩き方が虫のように見えたため、報酬を設計し直して犬らしいトロット歩行にした。

2. 目的

  • 脚ロボットは段差や不整地に強く、倉庫・施設内の巡回や配送への応用が期待される。現場の人が専門知識なしに「どこへ行ってほしいか」を言葉で伝えられれば使い勝手が大きく上がる。
  • そこで「言葉の理解（LLM）」と「身体の制御（強化学習）」を役割分担させ、それぞれ得意な部分だけを任せる構成で、言葉から歩行までを一貫して動かすことを目標とした。
  • 機密性の高い現場でも使えるよう、LLM は外部 API を使わずローカルで動かす。

3. 手法

(1) 犬型ロボット（自作）　実在の四足ロボット（Spot、ANYmal、Unitree Go2 など）と同じく、胴体の下に脚が伸び膝が後ろに曲がる構成にした。

体胴体（箱形、6 kg）と頭、脚 4 本（太もも・すね各 0.21 m）。各脚は外転・股・膝の 3 関節で計 12 関節、全体で 12.5 kg、立った胴体の高さ約 0.33 m。耳・鼻・しっぽ・外装は見た目だけの部品（質量 0・接触なし）で、物理には影響しない
制御関節は位置制御（PD、比例ゲイン 60、最大トルク 30 N·m）。方策の出力は「立ち姿勢からの関節角のずれ」（±0.4 rad）で、50 Hz で更新
観測（53次元）胴体の高さ・重力の向き・速度・角速度（胴体座標系）、12 関節の角度と速度、直前の行動、ゴールの方向（胴体座標系 2 / 世界座標系 2）と距離（5 m で頭打ち）、歩行クロックの位相（sin・cos）
報酬四足ロボットの強化学習で標準的な項目で構成した。
加点：ゴールへ近づく速さが目標 0.8 m/秒に近いこと（ガウス型）、頭がゴールの方を向いていること、足の接地が歩行クロック（周期 0.5 秒、対角の脚を交互に接地させるトロット）に合っていること、到着ボーナス 10（半径 0.6 m 以内）
減点：横方向の速度（カニ歩き）、胴体の傾き、胴体の高さの目標 0.33 m からのずれ、外転関節の開き、行動の急な変化、関節速度、トルク。
胴体が 0.2 m より下がるか大きく傾いたら転倒として終了
ゴールの出し方現在地から 1.5〜5 m・ランダムな方向に置き、到着するたびに次のゴールを出し直す（1 エピソード 30 秒の中で何度も到達を練習）。出発時の向きもランダム
学習PPO（Stable-Baselines3）、16 並列環境、方策・価値とも 256×256 の MLP、観測・報酬の正規化あり、CPU のみ。3,000 万ステップ（約 2.3 時間）

(2) LLM プランナー　地点名と座標の一覧をシステムプロンプトで与え、指示を {"route": [...], "reply": "..."} の JSON に変換させる。Ollama の構造化出力（JSON Schema）で route の要素を地点名の列挙型に制限し、存在しない地点を出力できないようにした。LLM が使えない場合は、文中の色名を拾う簡易的な変換に切り替わる。

(3) 実行　経由地を 1 つずつゴールとして方策に渡し、到着したら次の経由地へ切り替える。

4. 開発の経緯

  • ① 初版（Ant）：まず Gymnasium 標準の Ant を同じゴール到達課題に作り替えて学習させ、日本語指示での経由地巡回まで動かした（700 万ステップで到達率 99%）。ただ、胴体から脚が放射状に伸びたクモのような形で、配送ロボットとしては印象がよくなかった。
  • ② 犬型・旧版：胴体の下に脚が伸びる犬型を MJCF で一から作った。脚が胴体の真下にあるぶん倒れやすいので、関節を位置制御にし、方策には「立ち姿勢からのずれ」だけを出させた。報酬は「ゴールに近づいた速さ」を中心にし、腹ばいで進む抜け道を胴体の高さの減点と足の滞空時間の加点で塞いだ。200 万ステップで到達率 98% になったが、録画を見ると脚を横に広げたまま小刻みに走り回る動きで、形は犬でも動きは虫のように見えた。
  • ③ 犬型・改良版：原因を数値で確かめたところ、旧版は秒速 1.8 m（体高 0.3 m のロボットとしては非常に速い）で、足が地面に着いている時間は 3 割ほど、対角の脚がそろって動く割合は 34% だった（下表）。「近づく速さ」に上限がないため、速さだけを追って歩き方が崩れていた。そこで報酬を、脚ロボットの強化学習で標準的な構成（目標速度への追従、姿勢・高さ・なめらかさの減点）に組み替え、トロットのリズムを与える歩行クロックを加えた。見た目も実在のロボット犬に近づけ（頭・耳・しっぽ、太い太もも）、カメラを斜め前から追う構図に変えた。

5. 結果

モデルの選び方：改良版は学習中のチェックポイントごとに到達率がばらつき、失敗はすべて転倒だった。そこで 30 回の試験で 100% だったものを 100 回で測り直し（1,300 万・2,000 万・2,800 万・2,900 万・3,000 万ステップが 100%）、さらに下の 3 経路を 20 回ずつ走らせた。全経路で 100% だったのは 2,000 万と 2,900 万ステップの 2 つで、歩き方の指標もほぼ同じだったため、経路の所要時間がわずかに短い 2,900 万ステップを採用した。最終の 3,000 万ステップは一周経路で 1 回転倒した（95%）。

6. 工夫した点

  • 言葉と身体の役割分担：LLM には経由地の列を出させるだけにして、関節の動かし方には関わらせない。歩行方策は「ゴールまで歩く」ことだけを学ぶので、新しい指示や地点の組み合わせにも学習し直さずに対応できる。
  • 歩き方を数値で診断して報酬を設計：「虫っぽい」という印象を、速さ・接地時間・対角の脚のそろい方・脚の開き・横方向の速さの指標に置き換えて原因を特定し、脚ロボットの強化学習で標準的な報酬構成と歩行クロックで直した。対角の脚がそろう割合は 34% から 73% に上がった。
  • ロボットの自作と位置制御：実在の四足ロボットに近い犬型を作り、位置制御と「立ち姿勢からのずれ」を出力とする設計で、学習の初めから立った状態を保てるようにした。見た目の部品は質量 0・接触なしにして、物理を変えずに外観だけを整えた。
  • ゴールを胴体から見た向きで与える：ゴール方向を胴体座標系に変換して観測に加え、「ゴールの方を向いている」ことにも報酬を与えた。これで頭を進行方向に向けて歩く。
  • 到着したらゴールを出し直す：1 エピソードに何度もゴールを出すため、「止まる・曲がる・また歩く」を集中的に経験できる。学習中は 5 m 以内のゴールしか出さなかったが、10 m を超える区間でも到達できた。
  • LLM 出力の型を制限：JSON Schema の列挙型で、存在しない地点や不正な形式が実行系に渡らないようにした。
  • 評価に基づく判断：ロボットの形・報酬の変更やモデルの採用は、100 回の到達試験と経路ごとの 20 回試験、歩き方の指標で比べて決めた。
  • 見せ方：カメラはロボットの向きに合わせて斜め前に回り込み、顔と脚の運びが見えるようにした。柱がロボットの手前に入ったら半透明にして隠れないようにした。

7. 課題と考察

  • チェックポイントによる安定性のばらつき：改良版は 200 万ステップ以降、どの時点でも到達率 83〜100%（30 回）だったが、転倒する割合は時点によって 0〜17% と揺れた。学習が進めば単調に良くなるわけではないため、最終モデルをそのまま使わず、評価で選ぶ手順が必要だった。押されても倒れないよう外乱を加えた学習や、転倒からの起き上がり動作の学習で、さらに安定させられると考えられる。
  • 速さとのトレードオフ：目標速度を 0.8 m/秒に抑えたため、所要時間は旧版の約 2.5 倍になった。指示に「急いで」などがあれば LLM が目標速度も出力し、方策が速度指令に従う形に拡張できる。
  • LLM の応答時間：4 GB の GPU で 4B 級のモデルを動かすため、1 回の変換に数十秒〜1 分半かかった。実用には小型モデルへの特化（ファインチューニング）や、よく使う指示のキャッシュが必要。
  • 今後：障害物のある環境での経路計画、カメラ画像からの地点認識（VLM）、地形やモデル誤差をランダム化した学習による実機の四足ロボットへの sim-to-real。

8. 実行方法

コード一式は GitHub リポジトリ https://github.com/azs4n10/pai-final-quadruped に置いた（README 参照）。主なファイル：goal_dog.py（犬型ロボット・改良版と環境）、goal_dog_v1.py（犬型・旧版）、goal_ant.py（初版の環境）、train_goal.py（学習）、planner.py（LLM）、demo.py（指示の実行と録画）、evaluate.py（評価）、make_video.py（動画の作成）。
例：python demo.py --robot dog --text "黄色い柱に荷物を届けたら帰ってきて"

使用ツール：MuJoCo 3.12 / Gymnasium 1.3 / Stable-Baselines3 2.9（PPO）/ Ollama（gemma4:e4b）/ Python 3.12。動画のデモは等速で、3 本目（一周）のみ 2 倍速（画面に表示）。
