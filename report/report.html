ことばで動く四足配送ロボット

ローカルLLM × 強化学習（PPO）による、日本語指示での目標到達歩行 ― Physical AI 応用1 最終課題

1. 概要

日本語で「赤い柱に寄ってから青い柱へ行き、最後はホームに戻って」と指示すると、4脚ロボットが指示どおりの順に各地点を歩いて回るシステムを、物理シミュレータ MuJoCo 上に実装した。指示の解釈はローカルで動く LLM（gemma4 / Ollama）が担当し、歩行そのものは強化学習（PPO）で獲得した「指定したゴールまで歩く」方策が担当する。

2. 目的

  • 脚ロボットは段差や不整地に強く、倉庫・施設内の巡回や配送への応用が期待される。現場の人が専門知識なしに「どこへ行ってほしいか」を言葉で伝えられれば使い勝手が大きく上がる。
  • そこで「言葉の理解（LLM）」と「身体の制御（強化学習）」を役割分担させ、それぞれ得意な部分だけを任せる構成で、言葉から歩行までを一貫して動かすことを目標とした。
  • 機密性の高い現場でも使えるよう、LLM は外部 API を使わずローカルで動かす。

3. 手法

(1) ゴール到達環境（GoalAnt）　Gymnasium の Ant-v5（4脚・8関節）をもとに、観測と報酬を「前に進む」から「ゴールへ向かう」に作り替えた。見た目は機械らしい配色・部品に変えたが、追加した部品は質量 0・接触なしで、物理モデルは元の Ant と同一である。

観測（32次元）関節角度・速度など本体の状態（27次元）＋ ゴール方向の単位ベクトル（胴体座標系 2 / 世界座標系 2）＋ ゴールまでの距離（5 m で頭打ち）
報酬ゴールに近づいた速さ（距離の減少量 / Δt）＋ 姿勢維持 0.25 − 0.1 × 制御入力² ＋ 到着ボーナス 5（半径 0.6 m 以内）。転倒で終了
ゴールの出し方現在地から 1.5〜5 m・ランダムな方向に置き、到着するたびに次のゴールを出し直す（1 エピソード 50 秒の中で何度も到達を練習）
学習PPO（Stable-Baselines3）、16 並列環境、方策・価値とも 256×256 の MLP、観測・報酬の正規化あり、計 1,500 万ステップ（CPU のみで約 2 時間）

(2) LLM プランナー　地点名と座標の一覧をシステムプロンプトで与え、指示を {"route": [...], "reply": "..."} の JSON に変換させる。Ollama の構造化出力（JSON Schema）で route の要素を地点名の列挙型に制限し、存在しない地点を出力できないようにした。LLM が使えない場合は、文中の色名を拾う簡易的な変換に切り替わる。

(3) 実行　経由地を 1 つずつゴールとして方策に渡し、到着したら次の経由地へ切り替える。

4. 結果

学習開始から 200 万ステップほどで到達率が 97% に達した。それ以降は頭打ちになり、終盤（1,500 万ステップ）ではかえって成績が下がった。そこで、各チェックポイントを 100 回ずつ評価し直して採用モデルを決めた。

5. 工夫した点

  • 言葉と身体の役割分担：LLM には経由地の列を出させるだけにして、関節の動かし方には関わらせない。歩行方策は「ゴールまで歩く」ことだけを学ぶので、新しい指示や地点の組み合わせにも学習し直さずに対応できる。
  • ゴールを胴体から見た向きで与える：ゴール方向を胴体座標系に変換して観測に加え、「自分から見て右前にゴールがある」と直接分かるようにした。
  • 到着したらゴールを出し直す：1 エピソードに何度もゴールを出すため、「止まる・曲がる・また歩く」を集中的に経験できる。学習中は 5 m 以内のゴールしか出さなかったが、10 m を超える区間でも到達できた。
  • LLM 出力の型を制限：JSON Schema の列挙型で、存在しない地点や不正な形式が実行系に渡らないようにした。
  • 評価に基づくモデル選択：最後のモデルが最良とは限らないため、チェックポイントを 100 回ずつ評価し、到達率・速さ・転倒率がそろって良いものを採用した。
  • 見せ方：指示・計画・進行状況・軌跡を 1 画面に重ねて表示し、「言葉 → 計画 → 動作」の対応が一目で分かるようにした。

6. 課題と考察

  • 失敗の内訳：3 経路 × 20 回の計 60 回のうち、失敗は 8 回だった。5 回は歩いている途中での転倒（1 回は出発直後）。残り 3 回は転ばないまま次の地点に進めず時間切れになったもので、うち 1 回はその場でほとんど動かなくなり、1 回は目標から 3〜4 m の範囲をうろうろし続けた。転倒には、胴体の傾きへのペナルティや、学習時の初期姿勢・外乱のランダム化が有効と考えられる。止まってしまう失敗は、方策だけでなく上位側に「一定時間近づけなければ別の方向へ少し歩いてからやり直す」といった回復動作を入れることで補える。
  • 学習終盤の性能低下：700 万ステップ以降は到達率がわずかに下がった。報酬が速さを重視するので、無理に速く歩いて姿勢が不安定になった可能性がある。
  • LLM の応答時間：4 GB の GPU で 4B 級のモデルを動かすため、1 回の変換に数十秒〜1 分半かかった。実用には小型モデルへの特化（ファインチューニング）や、よく使う指示のキャッシュが必要。
  • 今後：障害物のある環境での経路計画、カメラ画像からの地点認識（VLM）、実機の四足ロボットへの sim-to-real。

7. 実行方法

コード一式は GitHub リポジトリに置いた（README 参照）。主なファイル：goal_ant.py（環境）、train_goal.py（学習）、planner.py（LLM）、demo.py（指示の実行と録画）、evaluate.py（評価）、make_video.py（動画の作成）。
例：python demo.py --text "黄色い柱に荷物を届けたら帰ってきて"

使用ツール：MuJoCo 3.12 / Gymnasium 1.3（Ant-v5）/ Stable-Baselines3 2.9（PPO）/ Ollama（gemma4:e4b）/ Python 3.12。動画は等速（倍速なし）。
